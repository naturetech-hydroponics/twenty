# Troubleshooting: Server Health Check Failed

## What Happened

Your deployment progressed successfully through these stages:
- ✅ Images pulled
- ✅ Volumes created
- ✅ Network created
- ✅ Database started and became healthy
- ✅ Redis started
- ✅ Change-vol-ownership completed
- ✅ Server started
- ❌ **Server failed health check**
- ❌ Worker couldn't start (depends on healthy server)

## Error Analysis

```
Container server-pco0owwgw80owk84k0sgcoco-230514197385  Error
dependency failed to start: container server-pco0owwgw80owk84k0sgcoco-230514197385 is unhealthy
```

The server container started but failed the health check defined in docker-compose.yaml:
```yaml
healthcheck:
  test: curl --fail http://localhost:3000/healthz || exit 1
  interval: 10s
  timeout: 5s
  retries: 30
  start_period: 40s
```

## Common Causes & Solutions

### 1. Missing Environment Variables (Most Likely)

**Issue**: Coolify magic variables not populated or `DOMAIN` not set.

**Check in Coolify**:
1. Go to your application → **Environment** tab
2. Verify these variables exist:
   - `SERVICE_FQDN_SERVER` (should be auto-populated)
   - `SERVICE_PASSWORD_POSTGRES` (should be auto-populated)
   - `SERVICE_BASE64_32_SECRET` (should be auto-populated)
   - `DOMAIN` (you must set this manually)

**Fix**:
Add missing environment variable:
```
DOMAIN=your-domain.com
```

Then redeploy.

---

### 2. Database Connection Issues

**Issue**: Server can't connect to PostgreSQL.

**Check Server Logs**:
In Coolify, view the server container logs to see the actual error:
1. Go to your application
2. Click on **"server"** service
3. View logs - look for errors like:
   - `ECONNREFUSED`
   - `password authentication failed`
   - `database "default" does not exist`

**Fix**:
Verify `PG_DATABASE_URL` is correctly formatted:
```
postgres://postgres:$SERVICE_PASSWORD_POSTGRES@db:5432/default
```

---

### 3. Server Taking Too Long to Start

**Issue**: Server needs more time than the 40-second start period.

**Check**:
Look at server logs for slow startup indicators:
- Database migrations running
- Dependencies being installed
- Large data initialization

**Fix**:
Increase health check timings in `docker-compose.yaml`:
```yaml
healthcheck:
  test: curl --fail http://localhost:3000/healthz || exit 1
  interval: 10s
  timeout: 5s
  retries: 50        # Increased from 30
  start_period: 60s  # Increased from 40s
```

---

### 4. Port 3000 Not Accessible

**Issue**: Server not listening on port 3000.

**Check**:
Verify `NODE_PORT` environment variable:
```
NODE_PORT=3000
```

---

### 5. Frontend URL Mismatch

**Issue**: `FRONTEND_URL` and `SERVER_URL` don't match Coolify's domain.

**Fix**:
These should be set to `$SERVICE_FQDN_SERVER` (Coolify auto-populates):
```yaml
- FRONTEND_URL=$SERVICE_FQDN_SERVER
- SERVER_URL=$SERVICE_FQDN_SERVER
```

## Immediate Next Steps

### Step 1: Check Server Logs

In Coolify:
1. Navigate to your application

   ```
   Error: connect ECONNREFUSED

   Error: Cannot find module
   ```

Go to **Environment** tab and ensure you have:

```bash
DOMAIN=your-domain.com
```

In Coolify, verify the database container is healthy:
- Should show green/healthy status
- Check database logs for errors

After fixing environment variables:
1. Click **"Redeploy"**
2. Monitor logs during startup
3. Watch for specific error messages

## How to Read Server Logs

Look for these patterns:

### ✅ Good Signs:
```
Server started successfully
Listening on port 3000
Database connected
Migrations completed
```

### ❌ Bad Signs:
```
ECONNREFUSED - Can't connect to database/redis
password authentication failed - Wrong DB password
APP_SECRET is required - Missing environment variable
Cannot find module - Build/dependency issue
Error: listen EADDRINUSE - Port already in use
```
